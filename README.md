| ขั้น | ทำอะไร | ผลที่ได้ |
|---|---|---|
| **1** | จับคู่ชื่อรายการด้วยโครงพยัญชนะ | ทนต่อ text layer ที่เพี้ยน |
| **2** | หาคอลัมน์จากพิกัดตัวอักษร | ทนต่อช่องว่างและค่าติดลบในวงเล็บ |
| **3** | ตรวจตัวเองด้วยสมการบัญชี | จับความผิดพลาดได้โดยไม่ต้องมีเฉลย · 267 ข้อ |

### ขั้นที่ 1 — จับคู่ด้วยโครงพยัญชนะ

**สิ่งที่เพี้ยนใน text layer มีแต่สระ วรรณยุกต์ และช่องว่าง พยัญชนะแทบไม่เคยเพี้ยน**

```
ที่ตาเห็น    ลูกหนี้การค้าและลูกหนี้หมุนเวียนอื่น
ที่ dump ได้  ลกู หน้กีารคา้                        (IIG)
             เงินฝากธนาคารทีมB ีภาระคาประก          (GABLE)
             องค์ประกอบอืน8 ของส่วนของผู้ถือหุ้น      (BBIK — วรรณยุกต์กลายเป็นเลข 8)
```

วิธีแก้คือตัดทุกอย่างที่ไม่ใช่ `[ก-ฮ]` ทิ้งก่อนจับคู่

```
"ลูกหนี้การค้า"  ->  ลกหนกรค
"ลกู หน้กีารคา้"  ->  ลกหนกรค     ตรงกัน
```

| ประเด็น | รายละเอียด |
|---|---|
| **ทำข้อมูลหายโดยตั้งใจ** | `ลูกหนู` กับ `ลูกหนี้` ให้โครงเดียวกัน การชนกันจึงเป็นไปได้เสมอ |
| **วิธีรับมือ** | เทียบกับพจนานุกรมปิด 256 รายการ + คีย์คู่กับตัวเลข + บริบทหัวข้อ (ดูหัวข้อ alias) |
| **ข้อบังคับในโค้ด** | ห้ามพิมพ์โครงพยัญชนะด้วยมือ ต้องเรียก `skeleton()` เสมอ — มี test บังคับ |

### ขั้นที่ 2 — หาคอลัมน์จากพิกัด ไม่ใช่จากการนับ

| วิธี | ปัญหา |
|---|---|
| นับ token | พังทันทีที่แถวมี `-` เพราะจำนวน token ไม่คงที่ ค่าเลื่อนทั้งแถว |
| **ใช้ตำแหน่งที่ token จบ** | ตัวเลขในงบชิดขวาเสมอ จึงทนต่อช่องว่างเปล่าได้ |

**เกณฑ์ระยะทางเป็นแบบยืดหยุ่น ไม่ใช่ค่าคงที่**

```python
min(8, ระยะไปคอลัมน์ที่ใกล้รองลงมา / 2)
```

| เกณฑ์ | ผล |
|---|---|
| ค่าคงที่ 4 ตัวอักษร | MFEC หน้า 6 เลขจบเหลื่อมไป 5 → ค่าหายทั้งช่อง |
| ค่าคงที่ที่ใหญ่ขึ้น | กวาดเลขอ้างอิงหมายเหตุเข้ามาเป็นค่า |
| **แบบยืดหยุ่น** | คอลัมน์ห่างกันราว 20 ตัวอักษร จึงไม่มีทางจับผิดคอลัมน์ และมีเพดานกันเลขนอกตาราง |

### ขั้นที่ 3 — ตรวจตัวเองด้วยสมการบัญชี

**งบที่ถูกต้องต้องบวกลบลงตัว จึงตรวจได้บางส่วนโดยไม่ต้องมีเฉลย**

```
สินทรัพย์หมุนเวียน + ไม่หมุนเวียน = สินทรัพย์รวม
หนี้สิน + ส่วนของเจ้าของ          = รวมหนี้สินและส่วนของเจ้าของ
เงินสดต้นงวด + เพิ่ม(ลด)สุทธิ      = เงินสดปลายงวด
ยอดปลายงวดในงบส่วนของเจ้าของ      = ส่วนของเจ้าของในงบฐานะการเงิน   (ข้ามงบ)
```

**ผ่าน 267 ข้อ ผิด 0** และใช้ได้กับบริษัทที่ยังไม่มีเฉลย

### ขั้นที่ 4 — สมการอย่างเดียวไม่พอ

**การทดลอง** จำลองอ่านคอลัมน์เลื่อนทั้งหน้าไป 1 ช่อง

| ตัวตรวจ | ผล |
|---|---|
| สมการตามแถว | **ผ่าน 428/428 — จับไม่ได้เลยสักหน้า** |
| เฉลย `tech-14` | **จับได้ 11/11 หน้า** |

**สาเหตุ** — เมื่อคอลัมน์เลื่อน ยอดต้นงวด รายการเคลื่อนไหว และยอดปลายงวดเลื่อนพร้อมกันหมด
สมการยังลงตัว ทั้งที่ตัวเลขทุกตัวไปอยู่ผิดองค์ประกอบ

**เกิดขึ้นจริงมาแล้ว** — ตัวสกัดเคยนับคอลัมน์เกินมา 1 ใน 4 หน้า สมการผ่าน 100%
ตลอดเวลาที่บั๊กนั้นอยู่ จับได้ด้วยการนับคอลัมน์เทียบกับ PDF ด้วยตา

### ขั้นที่ 5 — ทดสอบว่าชุดทดสอบจับผิดได้จริง

| วิธี | ทำอะไร | ผล |
|---|---|---|
| **Mutation test** | สุ่มแก้ค่าให้ผิดทีละช่อง 300 ครั้ง | จับได้ **300/300** |
| **Power test** | จำลองเลื่อนคอลัมน์ทั้งหน้า | สมการตาบอด 428/428 · เฉลยจับได้ **11/11** |
| **Order-stability test** | สลับลำดับแถวแล้วประเมินใหม่ 8 รอบ | **2,572/2,572 ทุกรอบ** |

**ที่มาของ order-stability test** — TRUE เคยได้คะแนนแกว่งระหว่าง 220/224 กับ 224/224
โดยที่โค้ดไม่เปลี่ยน สาเหตุคือ `drop_duplicates` เก็บแถวแรกที่เจอ พอลำดับในไฟล์เปลี่ยน
ผลก็เปลี่ยน คือคะแนนขึ้นกับลำดับ ไม่ได้ขึ้นกับความถูกต้อง

### กฎที่ใช้ตลอดโปรเจกต์

| กฎ | เหตุผล |
|---|---|
| **บั๊กทุกตัวที่เจอต้องกลายเป็น test ถาวร** | กันไม่ให้บั๊กเดิมกลับมา |
| **จะแก้อะไรต้องมี test ที่ fail ก่อนเสมอ** | เคยรีบแก้ `run_all.py` โดยไม่เขียน test แล้วสร้างบั๊กใหม่ขึ้นมาเอง |
| **รอบไหนที่สิ่งที่เจอเขียนเป็น test ไม่ได้ ให้ถือว่าจบ** | เกณฑ์หยุดรีวิว ไม่ให้ไล่แก้ไม่รู้จบ |

### Ground truth

**2,705 ช่องที่คนเปิด PDF อ่านแล้วพิมพ์เอง ไม่ได้เอาผลจากโค้ดมาใส่**

ถ้าเอาผลจากตัวสกัดมาเติมลงเฉลย จะกลายเป็นโค้ดตรวจตัวเอง ความแม่นยำจะเป็น 100%
เสมอและไม่มีความหมาย `make_gt_template.py` จึงจงใจเว้นช่องค่าไว้ว่าง

| ประเด็น | รายละเอียด |
|---|---|
| **ความครอบคลุม** | 30 จาก 50 ชุด (บริษัท × ประเภทงบ) |
| **วิธีเลือก** | แบ่งชั้นตามรูปแบบการจัดหน้า ไม่ใช่สุ่มทั่วไป |
| **การยืนยัน** | PRG และ STANLEY ได้ 100% ตั้งแต่ครั้งแรกโดยไม่แก้โค้ดเพื่อสองบริษัทนี้ |
| **ช่องว่างนับเป็นเทสต์** | ช่องที่งบพิมพ์ `-` ทดสอบว่าระบบไม่เสกค่าขึ้นมาเอง |
| **ถ้านับเฉพาะช่องที่มีเลข** | จะเหลือ 2,275 ช่อง — ตัวเลขที่ทดสอบจริงคือ **2,705** |

#### คอลัมน์ `trap` — บอกว่าแต่ละแถวทดสอบความยากแบบไหน

| trap | ทดสอบอะไร |
|---|---|
| `parentheses` | วงเล็บ = ค่าติดลบ และตำแหน่งเลื่อนเพราะวงเล็บปิด |
| `thai_digit` | วรรณยุกต์กลายเป็นตัวเลขกลางชื่อ |
| `long_name` | ชื่อยาวถูกตัดขึ้นบรรทัดใหม่ |
| `same_name` | สองแถวชื่อเหมือนกันเป๊ะ แยกได้ด้วยหัวข้อกลุ่มเท่านั้น |
| `note_col` | คอลัมน์เลขอ้างอิงหมายเหตุที่ต้องไม่ถูกอ่านเป็นค่า |

**วัดแยกตาม trap เพราะระบบไม่พังที่บรรทัดปกติ แต่พังที่ trap**

#### ต้องรายงานความครอบคลุมคู่กับความแม่นยำเสมอ

| รายงาน | ความหมาย |
|---|---|
| ถูก 97.7% (ไม่บอกความครอบคลุม) | เทียบแค่ 43 จาก 95 แถว ที่เหลือจับคู่ไม่ได้จึงไม่ถูกนับ |
| **ตัวเลขจริง** | **44.2%** |

**"100%" ที่มาจากการไม่ได้ตรวจ กับ "100%" ที่มาจากการถูก หน้าตาเหมือนกันเป๊ะ**
เครื่องมือทุกตัวในโปรเจกต์นี้จึงพิมพ์ความครอบคลุมออกมาด้วยเสมอ

#### เฉลยเองก็ผิดได้

| กรณี | จับได้ด้วย | การจัดการ |
|---|---|---|
| Excel ตัดเลข 12 หลักเหลือ 6 หลักนัยสำคัญ | สมการกำไรขั้นต้นไม่ลงตัว | แก้ที่เฉลย |
| เฉลยกรอกมาแล้วเลื่อนแถว 78 ช่อง | เทียบกับผลสกัด | **ไม่แก้เอง** ให้คนกรอกกลับไปดู PDF — ถ้าแก้เองเฉลยจะกลายเป็นสำเนาของโค้ด |

`validate_ground_truth.py` ตรวจว่าเฉลยแต่ละชุดสอดคล้องกันเองก่อนเอาไปเทียบกับผลสกัด

### Alias map

บริษัทแต่ละแห่งเรียกรายการเดียวกันไม่เหมือนกัน แมปนี้คือสิ่งที่ทำให้เทียบข้ามบริษัทได้

```csv
concept,alias,note
TRADE_RECEIVABLES,ลูกหนี้การค้าและลูกหนี้หมุนเวียนอื่น,
TRADE_RECEIVABLES,ลูกหนี้การค้าและลูกหนี้อื่น,
TRADE_RECEIVABLES,ลูกหนี้การค้า,
```

**ทั้งฝั่งเอกสารและฝั่งแมปผ่านฟังก์ชัน `skeleton()` ตัวเดียวกัน** จึงไม่ต้องเก็บทุกแบบที่เพี้ยนได้
เก็บแค่ชื่อที่ถูกต้อง

#### การชนกันของโครงพยัญชนะ

**คำถามที่ถูกต้องไม่ใช่ "คำไทยสองคำชนกันได้ไหม" (ได้แน่นอน) แต่คือ "มีสองรายการในแมปนี้ที่ชนกันไหม"**
เพราะระบบเทียบกับพจนานุกรมปิด 256 รายการ ไม่ได้เทียบกับคำไทยทั้งภาษา
ถ้าเอกสารเขียนคำที่ไม่อยู่ในแมป ระบบรายงานว่า**จับคู่ไม่ได้** ไม่ใช่จับคู่ผิด

| ตัวเลขจริงในแมป | จำนวน |
|---|---|
| alias ทั้งหมด | 514 |
| โครงพยัญชนะที่ต่างกัน | 488 |
| **โครงที่ชี้ไปหลายรายการ** | **2 กลุ่ม** (แยกออกได้ด้วยตัวเลขทั้งคู่) |

กลุ่มที่ชนคือทุนจดทะเบียน / ทุนที่ออก / ทุนชำระแล้ว ซึ่งข้อความเหมือนกันเป๊ะ ต่างกันแค่ตัวเลข

```
หุ้นสามัญ 441,453,555 หุ้น มูลค่าหุ้นละ 1 บาท     -> ทุนที่ออกและชำระแล้ว
หุ้นสามัญ 700,021,420 หุ้น มูลค่าหุ้นละ 1 บาท     -> ทุนที่ออก
หุ้นสามัญ 3,024,682,097 หุ้น มูลค่าหุ้นละ 10 บาท  -> ทุนจดทะเบียน
```

**วิธีรับมือ 3 ชั้น**

| ชั้น | กลไก | รายละเอียด |
|---|---|---|
| **1** | คีย์คู่ | จับคู่ด้วย `(โครงพยัญชนะ, ตัวเลขในชื่อ)` — ตัวเลขไม่เคยเพี้ยนเหมือนสระ |
| **2** | บริบทหัวข้อกลุ่ม | ชื่อเดียวกันใต้ `สินทรัพย์หมุนเวียน` กับ `ไม่หมุนเวียน` = คนละรายการ · เรียงผู้สมัครจากเฉพาะเจาะจงที่สุดก่อน |
| **3** | test ถาวร | `selfcheck.py` ไล่ทุกคู่ในแมป ถ้าเจอโครงชนกันแต่คนละรายการ จะไม่ยอมให้รันต่อ |

```python
digits("หุ้นสามัญ 707,500,000 หุ้น มูลค่าหุ้นละ 1 บาท")  ->  "7075000001"
digits("หุ้นสามัญ 700,021,420 หุ้น มูลค่าหุ้นละ 1 บาท")  ->  "7000214201"
```

**การชนแบบนี้ไม่ทำให้โปรแกรม error มันแค่หยิบตัวไหนก็ได้แล้วเดินต่อไปเงียบๆ**
ในโค้ดจึงเขียนคอมเมนต์กำกับไว้ว่า *"alias ที่โครงพยัญชนะชนกันแต่ concept ต่างกัน = ระเบิดเวลา"*

#### `concept` กับ `concept_eq`

| ฟิลด์ | ใช้ที่ไหน | เนื้อหา |
|---|---|---|
| `concept` | ground truth และผลสกัด | สิ่งที่เอกสารเขียน |
| `concept_eq` | สมการตรวจสอบเท่านั้น | มีคำต่อท้ายบอกตำแหน่ง เช่น `_AFTER` |

**แยกกันเพราะเฉลยควรบันทึก "งบเขียนว่าอะไร" ไม่ใช่ "โค้ดต้องการให้เป็นอะไร"**

## OCR — วัดแล้วไม่ผ่าน จึงไม่นำเข้าระบบ

CP ALL และ Humanica เป็น PDF สแกน ไม่มี text layer เลย

**แนวทาง** — ให้ OCR คืนผลลัพธ์ที่หน้าตาเหมือน `pdftotext -layout` คือรักษาพิกัดไว้
เพื่อให้ตัวสกัดเดิมใช้ได้โดยไม่ต้องแก้โค้ดสักบรรทัด (`ocr_reader.py`)

### ผลวัด 3 ระดับ

| ระดับ | วัดอะไร | ผล |
|---|---|---|
| 1 | ตัวเลขปรากฏในหน้าไหม | 96.6% |
| 2 | ค่าอยู่ถูกช่องไหม (เทียบกับหน้าที่ text layer ได้ 100%) | **63.1%** |
| 3 | ใช้กับสแกนจริง | **36% / 41%** |

| ประเด็น | รายละเอียด |
|---|---|
| **ระดับ 1 หลอกตา** | นับแค่ว่าตัวเลขโผล่ที่ไหนสักแห่ง ไม่ตรวจว่าอยู่ถูกคอลัมน์ถูกแถว |
| **วิธีวัดระดับ 2** | เอาไฟล์ที่ text layer ดี (รู้ว่าถูก 100%) มาแปลงเป็นภาพแล้วส่งเข้า OCR เทียบเฉลยชุดเดิม จึงแยกได้ว่าความผิดพลาดมาจาก OCR ไม่ใช่ตัวสกัด |
| **การตัดสินใจ** | ไม่ผ่านเกณฑ์ **จึงไม่รวมเข้า `all.csv`** เก็บไว้แค่ตัวเลขกับเหตุผล |
| **ประโยชน์ที่เหลือไว้** | มี baseline 63.1% แล้ว ถ้าลองเครื่องมืออื่นเทียบได้ทันทีว่าดีขึ้นจริงไหม |

**ระบบที่รู้ตัวว่าทำไม่ได้ ดีกว่าระบบที่ปล่อยข้อมูลคุณภาพต่ำเข้ามาเงียบๆ**
